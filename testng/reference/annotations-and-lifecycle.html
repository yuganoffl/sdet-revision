The configuration annotations

Official definitions — testng.org/index.html#_annotations
Annotation"The annotated method will be run…"
@BeforeSuitebefore all tests in this suite have run
@BeforeTestbefore any test method belonging to the classes inside the <test> tag is run
@BeforeGroupsshortly before the first test method that belongs to any of these groups is invoked
@BeforeClassbefore the first test method in the current class is invoked
@BeforeMethodbefore each test method
@AfterMethodafter each test method
@AfterClassafter all the test methods in the current class have been run
@AfterGroupsshortly after the last test method that belongs to any of these groups is invoked
@AfterTestafter all the test methods belonging to the classes inside the <test> tag have run
@AfterSuiteafter all tests in this suite have run

The other five annotations are not lifecycle: @Test, @DataProvider, @Parameters, @Factory, @Listeners.

Order, single class, two test methods

@BeforeSuite
  @BeforeTest
    @BeforeClass
      @BeforeMethod  ->  testOne  ->  @AfterMethod
      @BeforeMethod  ->  testTwo  ->  @AfterMethod
    @AfterClass
  @AfterTest
@AfterSuite

Before methods run outside-in. After methods run inside-out. Only the Method pair repeats per test.

Order, two classes in one run

What repeats and what does not
ScopeFiresTiming with 2 classes
Suiteonce per annotated methodall of them, before any class starts
Testonce per annotated method per <test>all of them, before any class starts
Classonce per classimmediately before that class's own first test
Methodonce per test methodwrapped around every single test

Not guaranteed

  • Class order. Not alphabetical, not declaration order.
  • Method order within a class. Not the order you typed them. Use priority or dependsOnMethods to force it.

Where real setup goes

NeedScope
read config file, start driver server, open connection pool@BeforeSuite
one environment shared by several classes@BeforeTest
launch browser, log in once for related checks@BeforeClass
reset state, clear cookies, go to a known page@BeforeMethod
screenshot on failure, log out, clear test data@AfterMethod
close pool, write summary@AfterSuite

Trade to state out loud: wider scope is faster, narrower scope isolates failures better. Browser in @BeforeClass, reset in @BeforeMethod is the defensible default.

Traps

Say these correctly

@BeforeTest is not "before each @Test". That is @BeforeMethod. @BeforeTest is tied to the <test> tag in testng.xml.

A class not named Test*, *Test, *Tests or *TestCase is invisible to Maven Surefire. Zero tests run, build green.

TestNG assertion order is assertEquals(actual, expected). JUnit is the reverse.

A test method with no assertion always passes. Passing means "did not throw".
