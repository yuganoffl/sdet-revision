Lesson 07 · Selenium

Every element type you have to handle

Most of the page is findElement then click or sendKeys. Five things are not, and those five are what interviewers ask about. This lesson is those five, plus tables and the JavaScript escape hatch. All of it ran green in ElementTypesTest.

The whole lesson in one box

Ordinary elements: click(), sendKeys(), getText(), clear(), isDisplayed(), isEnabled(), isSelected(), getAttribute().

The five exceptions to that:

<select> needs the Select class.
Alerts need switchTo().alert().
Frames need switchTo().frame(), and switching back out.
New tabs need window handles.
Hover needs the Actions class.

1. Dropdowns

Only for a real <select> tag. Wrap the element, then choose.

Select country = new Select(driver.findElement(By.id("country")));

country.selectByVisibleText("United Kingdom");   // what the user sees
country.selectByValue("us");                     // the value attribute
country.selectByIndex(0);                        // 0-based

country.getFirstSelectedOption().getText();      // read it back
country.getOptions().size();                     // all options
country.isMultiple();

Multi-select adds the other half:

skills.getAllSelectedOptions();
skills.deselectByValue("java");
skills.deselectAll();                            // throws on a single select
The follow-up: what if it is not a <select>?

Most modern dropdowns are divs styled to look like a dropdown. The Select class throws UnexpectedTagNameException on those.

Then it is just clicking. Click the toggle, wait for the options to be visible, click the one you want. Say this in an interview and you have shown you have tested a real application rather than a tutorial page.

2. Checkboxes and radios

click() toggles. It does not tick.

Calling click() on a box that is already ticked unticks it. Every framework ends up with this helper, and writing it out is a good interview answer.

private void setChecked(WebElement box, boolean wanted) {
    if (box.isSelected() != wanted) {
        box.click();
    }
}

isSelected() is the one that reads checked state. Do not use getAttribute("checked"), which reports the original HTML rather than the current state.

Radios work the same way, except clicking one clears the others in its group automatically. You never need to unclick a radio.

3. Alerts

A browser alert is not part of the page. No locator can reach it. You switch to it.

Alert alert = wait.until(ExpectedConditions.alertIsPresent());

alert.getText();
alert.accept();          // OK
alert.dismiss();         // Cancel
alert.sendKeys("Yugan"); // only for a prompt
TypeButtonsCan you type?
alert()OK onlyno
confirm()OK and Cancelno
prompt()OK and Cancelyes

Leave an alert open and every following command throws UnhandledAlertException. Always accept or dismiss it.

A native alert is the browser's own dialog. A "modal" built out of HTML is not an alert at all, and you locate it normally. Knowing that distinction is the point of the question.

4. Frames

An element inside an iframe is invisible to the driver until you switch in. Not slow to find. Invisible. You get NoSuchElementException and it looks like a locator problem.

driver.switchTo().frame("theFrame");        // by name or id
driver.switchTo().frame(0);                 // by index
driver.switchTo().frame(element);           // by WebElement

// ... work inside ...

driver.switchTo().defaultContent();         // back to the top document
driver.switchTo().parentFrame();            // up one level only

The switch back out is the half people forget. Everything after it fails, and the failure appears somewhere unrelated to the frame.

5. Windows and tabs

Opening a new tab does not move the driver. It keeps talking to the old one until you switch.

String original = driver.getWindowHandle();          // save where you are

driver.findElement(By.id("new-tab")).click();
wait.until(ExpectedConditions.numberOfWindowsToBe(2));

for (String handle : driver.getWindowHandles()) {
    if (!handle.equals(original)) {
        driver.switchTo().window(handle);
    }
}

// ... work in the new tab ...

driver.close();                        // closes THIS tab only
driver.switchTo().window(original);    // you must switch back

A handle is an opaque id string, not a title or a URL. And close() versus quit() matters here: close() shuts one tab, quit() ends the whole session and kills the driver process.

6. Actions: hover, drag, right click

WebElement has no hover method. Actions is the only way.

new Actions(driver)
    .moveToElement(menu)         // hover
    .perform();                  // nothing happens until perform()

new Actions(driver).contextClick(row).perform();          // right click
new Actions(driver).doubleClick(cell).perform();
new Actions(driver).dragAndDrop(source, target).perform();
new Actions(driver).keyDown(Keys.SHIFT).click(item).keyUp(Keys.SHIFT).perform();

The one rule: nothing runs until perform(). A chain without it is a silent no-op, and it is the classic Actions bug.

7. Tables

A table is just nested elements. Two things you actually do:

// Count rows
driver.findElements(By.cssSelector("#orders tbody tr")).size();

// Read a whole column
driver.findElements(By.cssSelector("#orders tbody tr td:nth-child(2)"));

And the one that matters, from lesson 6: find a row by its content, then read another cell in it.

driver.findElement(By.xpath("//table[@id='orders']//tr[td[text()='Bob']]/td[3]"));

Never index rows by number. The data reorders and your test starts checking the wrong customer while still passing.

8. The JavaScript escape hatch

((JavascriptExecutor) driver)
    .executeScript("arguments[0].scrollIntoView({block:'center'});", element);
Where the line is, and they will ask

Legitimate: scrolling something into view, reading a JS value the DOM does not expose, setting up state quickly in a fixture.

Usually wrong: a JS click to get past a failing normal click. If Selenium cannot click it, a user could not have clicked it either. A JS click bypasses that and turns a real bug into a green test.

The good answer: "I use it for scrolling. If I need it to click, I treat that as a signal that something is covering the element, and I fix the wait instead."
