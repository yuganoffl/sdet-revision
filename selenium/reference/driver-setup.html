Driver setup and teardown

Everything that happens before and after a test touches the page. Checked against the Selenium documentation, verified on Chrome 151 / Selenium 4.21 / JDK 21.

The skeleton

public abstract class BaseTest {
    protected WebDriver driver;

    @BeforeMethod(alwaysRun = true)
    public void startBrowser() {
        ChromeOptions options = new ChromeOptions();
        options.addArguments("--headless=new", "--window-size=1450,900");
        options.setPageLoadStrategy(PageLoadStrategy.EAGER);
        driver = new ChromeDriver(options);
        driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(60));
    }

    @AfterMethod(alwaysRun = true)
    public void stopBrowser() {
        if (driver != null) driver.quit();
    }
}

Driver binaries

How the chromedriver binary gets there
EraWhat you wroteStatus
Selenium 3System.setProperty("webdriver.chrome.driver", path)obsolete
Selenium 4.0–4.5WebDriverManager.chromedriver().setup(), a third-party libraryno longer needed

Selenium Manager is a Rust binary shipped inside every Selenium release since 4.6. It discovers, downloads and caches the driver. Since 4.11 it downloads the browser too, when one is not installed. Cache lives in ~/.cache/selenium.

Scope: where setup goes

Choose one, and be able to defend it
AnnotationBrowsers per class of 10 testsUse when
@BeforeMethod10default; tests cannot leak state into each other
@BeforeClass1the suite is slow and the tests genuinely do not share state
@BeforeSuite1 for everythingalmost never; one failure can strand the whole run

alwaysRun = true matters here. Without it, a group-filtered run (-Dgroups=smoke) can skip your setup method and every test then fails on a null driver.

close() vs quit()

close()quit()
Shutsthe focused window or tabevery window in the session
Browser processsurvives if other tabs remainends
Driver processkeeps runningends
Sessionaliveover; the driver object is now dead
Use inclosing a child tab mid-testteardown, always

After close() on the last window, or on a child tab, the driver still points at a window that is gone. Any command then throws NoSuchWindowException until you switchTo().window(parentHandle). (docs)

Page load strategy

What driver.get() waits for before returning
StrategyReturns whendocument.readyState
NORMAL (default)all resources are downloaded — images, CSS, fontscomplete
EAGERthe HTML is parsed; DOMContentLoaded has firedinteractive
NONEthe HTML has begun downloadingany
Practical note

EAGER is the fix for Timed out receiving message from renderer on a slow site. It is safe precisely because you are already using explicit waits for the elements you assert on. NONE is for pages where you deliberately want control before the DOM exists; it is rarely what you want.

Timeouts

driver.manage().timeouts().pageLoadTimeout(Duration.ofSeconds(60));  // get() gives up
driver.manage().timeouts().scriptTimeout(Duration.ofSeconds(30));    // async JS gives up
driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(10));  // DO NOT — see lesson 2
